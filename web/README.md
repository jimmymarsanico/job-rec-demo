# Web app

Next.js app for the job recommendation demo. See the [root README](../README.md) for the data
pipeline and findings.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # prerenders 1,000 job pages + the browse page
```

## Pages

- `/` — browse and filter all 1,000 jobs (job family, workplace type, seniority, country), with
  an offline scorecard comparing both models across six metrics.
- `/jobs/[id]` — one job, then both models' top-3 side by side. A yellow bar marks a pick only
  that model made; `≠` marks an attribute that disagrees with the job being viewed. The
  **Agreement** row under each panel counts how many of its three picks share the job's family,
  sit within one seniority level, share its workplace type, and how many distinct employers it
  surfaced.
- `/api/analyze` — blind LLM judge (see below).

## Data

`public/data/` is generated by the notebook, not by hand:

| File | Contents |
|---|---|
| `jobs.json` | 1,000 jobs with full HTML descriptions (~8 MB) |
| `recs_baseline.json` | top-3 per job from the title-only model |
| `recs_weighted.json` | top-3 per job from the seven-feature model |
| `meta.json` | feature weights, offline metrics, feed stats — drives the scorecard |

Regenerate with `cd ../notebook && python generate_data.py --copy-to-web`.

`getJobSummaries()` in `src/lib/data.ts` strips the HTML descriptions before any list view gets
the data. Passing full `jobs.json` into the browse page would put 8 MB of markup in the payload;
list views only need the metadata.

## Blind LLM judge

`POST /api/analyze` sends both recommendation lists to an LLM as "List 1" and "List 2" — in
randomised order, with no indication of which model produced which — and asks which set is more
useful to the candidate. The server maps the verdict back to the model that actually produced
the winning list.

This matters: labelling one list "Enhanced" in the prompt would do the judging for us, and the
verdict would prove nothing.

Requires `OPENAI_API_KEY` (Vercel project settings, or `web/.env.local` locally). Without it the
button returns a clear error and the rest of the app is unaffected.

## Deploying

Pushing to the connected GitHub repo triggers a Vercel deploy. Manually:

```bash
npx vercel --prod
```

The build produces 1,005 prerendered pages in well under a minute, comfortably inside the Hobby
plan's limits.
